# EMPSL v0.2 字形工程與六槽組合器技術規格\n\n**版本：** 0.2  \n**日期：** 2026-07-31  \n**狀態：** Engineering MVP\n\n## 1. 本輪目標\n\n本輪將 EMPSL v0.1 的抽象字形路線落成為可執行資產：\n\n- 32 個核心 SVG 構形種子；\n- 16 個語義外框；\n- 16 個 FARHP 相位簽名；\n- 16 個語義／算子附標；\n- 48 個音系、聲調與結構附標；\n- 六槽字形組合器；\n- 128 原子圖表；\n- 配方雜湊、碰撞診斷與 JSON Schema。\n\n總數為：\n\n$$\n32+16+16+16+48=128.\n$$\n\n## 2. 六槽模型\n\n$$\nG=[F\mid S\mid P\mid T\mid \Phi\mid O].\n$$\n\n其中 $F$ 是語義外框，$S$ 是中央種子，$P$ 是至多四個音系附標的集合，$T$ 是詞典聲調，$\Phi$ 是 PH16 可視相位簽名，$O$ 是算子附標。\n\n目前的 512×512 規範配置為：\n\n- 外框：全域外圍；\n- 種子：中央；\n- 音系：左側與左下群；\n- 聲調：上方；\n- 相位：右上；\n- 算子：右下。\n\n這些位置是 v0.2 渲染剖面，不是不可變本體。\n\n## 3. 48 個音系／聲調／結構原子\n\n$$\n21_{\text{onset}}+4_{\text{four-hu}}+12_{\text{rime}}+5_{\text{tone}}+6_{\text{structure}}=48.\n$$\n\n此版本沒有試圖以 48 個原子直接枚舉全部華語音節；它們是音節配方的視覺索引。完整注音、合法性、表層變調與 FARHP 聲學仍保存在結構化資料中。\n\n## 4. 規範身份與顯示資產\n\n原子 ID 與字形配方是規範資料；SVG 是可替換顯示資產：\n\n$$\n\operatorname{Identity}(a)\neq\operatorname{SVG}(a).\n$$\n\n每份 SVG 有獨立 SHA-256，但字型或書法風格改版不必改變原子 ID。若配方語義或槽位功能改變，才需要規格升版。\n\n## 5. 配方雜湊\n\n令六槽核心物件為 $R(G)$，使用排序鍵、緊湊 JSON 後計算：\n\n$$\nH_G=\operatorname{SHA256}(\operatorname{CanonicalJSON}(R(G))).\n$$\n\n讀法、義項與概念註解不進入 v0.2 的字形配方雜湊，因為它們可能多語化或版本化；六槽選擇改變時，雜湊必然改變。\n\n## 6. 碰撞診斷\n\n工具會將每個原子渲染為 64×64 灰階圖，裁切外框後正規化，檢查：\n\n1. 完全相同的像素雜湊；\n2. 最近鄰平均像素距離。\n\n此程序只能抓出工程級視覺碰撞，不等同人類可辨識度研究。正式字型前仍需要不同尺寸、不同視力、手寫與低解析度測試。\n\n## 7. 目前邊界\n\n- 21 個 ENO 種子是現代以諾式視覺設計，不是歷史字母復刻；\n- 尚未生成 OpenType 字型；\n- 尚未設計筆順與手寫簡化體；\n- PH16 是低維簽名，不是完整 FARHP 向量；\n- 音系附標目前最多顯示四枚；完整音節仍以 JSON 為準；\n- 尚未執行大規模字形碰撞與人類辨識實驗。\n\n## 8. 下一階段\n\n1. 建立 SVG 字形輪廓風格 v0.3；\n2. 加入旋轉、鏡像、開閉口等受控變換；\n3. 建立 256–512 個種子組合的碰撞測試集；\n4. 生成 OpenType GSUB／GPOS 原型；\n5. 建立注音／概念／字形三路輸入法；\n6. 將 WebLab 的音節與 FARHP 物件直接載入組合器。\n
